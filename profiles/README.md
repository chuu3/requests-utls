# Profile format v1

`chrome_152.json` is an experimental profile converted from one supplied macOS
Chrome 152 `tls.peet.ws` capture. It preserves that sample's extension order,
cipher order, SETTINGS order, initial window update, pseudo-header order and
HEADERS priority. It does not establish complete Chrome 152 behavior or the
browser's randomized extension-order distribution.

`profile.Load` accepts native JSON only. `profile.ImportPeet(data, false)` imports
supported captures; `ImportPeet(data, true)` explicitly permits the two
advertisement-only features described below and writes those opt-ins into the
native JSON. Unknown native fields, versions and unsupported semantic extensions
are errors. `profile.schema.json` supplies structural validation; the Go loader
also validates supported capabilities and cross-field constraints.

```go
p, err := profile.LoadFile("profiles/chrome_152.json")
// Handle err and inspect p.Limitations().
spec, err := p.NewClientHelloSpec() // Call once for EACH connection.
```

The immutable `Profile` can be shared concurrently. The returned ClientHelloSpec
and its extension instances belong to one TLS connection. uTLS mutates them in
ApplyPreset. `HTTP2()` returns a deep copy. `Hash()` hashes canonical native JSON
and can be used when isolating connection pools.

TLS fields use numeric registry IDs. Any GREASE value becomes placeholder 2570
(`0x0a0a`) at load time and is randomized per connection. SNI comes from the
request destination. Key shares, including X25519MLKEM768, are generated by uTLS;
GREASE ECH uses fresh key material, config ID and ciphertext. The importer
retains only ECH payload size, not captured ciphertext. Client randoms, session
IDs, network metadata, captured request headers and cookies are discarded.
Ordinary ordered request headers are supplied separately to the Session API.

The fixture explicitly opts into these limitations:

- Extension **51764 / 0xca34** is `trust_anchors` from TLS Trust Anchor IDs. Its
  original payload is sent as a raw extension in the captured position. The
  prototype does not implement its certificate selection or retry behavior.
  Native raw extensions currently allow this ID only and require
  `allow_opaque: true`; known semantic TLS extensions cannot bypass their typed
  builders using raw JSON.
- Signature schemes **0x0904, 0x0905 and 0x0906** are included in the advertised
  list with `allow_unsupported: true`. uTLS v1.8.2 cannot verify these schemes;
  a server selecting one causes a handshake error.
- GREASE ECH is an advertisement, not real ECH support. The importer cannot
  determine whether a capture originally used GREASE or genuine ECH.
- ALPS 17613 negotiation is handled by uTLS, including client EncryptedExtensions.
  This prototype does not apply peer HTTP/2 ALPS settings or configure custom
  client ALPS payloads; uTLS uses an empty client payload by default.
- GREASE extension lengths are absent from the capture. The two extensions use
  uTLS's BoringSSL convention: empty first body and a single zero byte second
  body. This is a documented assumption, not an observed byte comparison.

HTTP/2 SETTINGS and extensions use ordered arrays. Values of zero are retained.
`connection_window_update` is the increment beyond the initial 65,535-byte
connection window. `header_priority.weight` uses the human range 1..256;
the encoder converts it to the wire range 0..255.
